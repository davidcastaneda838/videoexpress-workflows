# Verified: VideoExpress WRITE API (create images + videos without clicking)

Date: Nov 17 2026. Setup: real Chrome profile, CDP-attached, logged in.

## How this was captured

1. `PerformanceObserver` (entryTypes: resource, initiatorType fetch/xhr) recorded request URLs during one real user-driven Create cycle.
2. JS monkey-patch of `window.fetch` + `XMLHttpRequest.send` recorded full request bodies (method, url, body) — stored in `window.__reqs`.
3. Replay test: re-POSTed the captured `image2video` body with a tweaked prompt via `fetch()` from the logged-in page.

## Verified write endpoints (form-encoded POSTs, same-origin, cookie+CSRF via fetch)

### 1. `POST /ai/api/extend_prompt/image`
`prompt=<urlencoded>&imageType=human` — prompt auto-enhancer (runs first when the checkbox is on).

### 2. `POST /ai/api/generate_image`
```
prompt=<image prompt>&enhancePrompt=0&type=human&uuid=&mediaId=0&seed=
&aspect=16:9&generatorName=create_from_prompt
```
- `enhancePrompt` 0/1 = the "Automatically enhance my image prompt" checkbox.
- `type` = human / other image types. `aspect` = 16:9 or 9:16 (as "16%3A9").
- `uuid`/`mediaId` empty for a fresh generation.

### 3. `POST /ai/api/image2video`  ← the core write
```
type=human
imagePrompt=<the visual prompt>
prompt=<the video/audio prompt — embedded dialogue goes here>
uuid=<source image uuid from generate_image result>
mediaId=0 & audioMediaId=0
isShared=0                 <- gallery share switch (0 = private)
aspect=16:9|9:16
enhanceHumanFace=0 & isTalkingVideoFromText=0 & isNarrationVideo=0
enhanceVideoPrompt=1 & videoOnly=0 & speed=
generatorName=create_from_prompt
faceImageMediaId=0 & faceSwap=0 & mode=
```

## Replay test result (verified live)

```
POST /ai/api/image2video  (tweaked prompt: 'delicious' -> 'amazing')
-> 200 {"success":true,"uuid":"e23473cd-c93d-4943-a7a9-05b78de96c0a","estimatedTimeSeconds":0}
```
Job verified via read API: two new items in My AI Videos, `status: "processing"`, caption = the tweaked video prompt, then `status: "completed"` with duration.

## Operational rules learned

1. **DOUBLE-SUBMIT AT API SCALE**: running the replay twice created TWO identical jobs (proven live). Rule: fire each write ONCE; identify the returned `uuid` and poll via `/api/library/get_media/4?...` until `status: "completed"` before any retry. Never re-POST on timeout without checking the library first.
2. Request headers used: `Content-Type: application/x-www-form-urlencoded; charset=UTF-8` + `X-Requested-With: XMLHttpRequest`. Same-origin `fetch()` from the logged-in page carries cookies + CSRF automatically.
3. The caption shown in the library = the VIDEO prompt (`prompt` field), not the image prompt — use it for scene mapping.
4. Credits burn per write: batch logic must verify-before-retry (see rule 1).
5. Not yet captured: lipsync dialog submission (`talking_video` flow), timeline assembly, export. Those remain UI-driven until captured in a future session.

## Impact

Image + video generation is now a 2-3 call API loop: `generate_image` -> poll status -> `image2video` -> poll status. At ~360 clips for an hour of video, this turns hours of clicking into a scripted batch process with deterministic verification.
